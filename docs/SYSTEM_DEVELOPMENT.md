# NET composition development checkpoint

This work extends the existing NET Session and operation substrate. Each pass
must complete a bounded implementation, execute it, inspect retained evidence,
independently audit its contracts and publish only qualified source. An hourly
continuation is enabled; the work lock is
`/workspace/scratch/net-system-development.lock`. Acquire a nonblocking exclusive
lock for the entire pass. Do not overlap another pass or overwrite dirty work.

## Implemented scope

- Strict versioned scientific specification compiler for coupled thermal,
  axial thermoelastic and synthetic observation reference models.
- Local and bounded subprocess execution, OCI adapter and packaging, distinct
  numerical verification and declared spatial reduction comparisons.
- Retained specification source identities, exact live/restore bindings and
  correction propagation through dependent operations and claims.
- Fixed-mesh timestep studies at common sample times including startup, with
  bounded analytic reference, explicit unassessed samples and empirical error
  changes.
- Compact inspection and synchronized standalone retained-state review.

Operation results, executions, source evidence, numerical reports and physical
authority remain distinct. Physical validation is `not_assessed`; canonical
admission is false. Sensors and material constants are illustrative. A sealed
record proves local consistency, not independent attestation.

## Publication and qualification

The scientific extension is additive to current main. Preserve its repository
URLs, correction/Legibility changes and import manifest. The local 21-instrument
native-history consolidation is a separate checkpoint until native Git transport
can publish its ancestry; do not simulate that migration by uploading a directory
snapshot. Source-only publication must not claim all 21 imports are on main.

Before publishing, run system suites, affected root regression, wheel-installed
checks outside the source checkout, and import-tree audit. Record exact source
and runtime identities with outputs. A configured CI job is not a passed check.
Only an observed real container run establishes OCI parity. An expected failed
approximation or startup threshold is retained evidence, not a CI defect.

Publish through a new branch based on current main. Reconcile later changes
additively, never force-push. Merge only the exact tested, mergeable head under
the user's standing push-and-merge authorization. Continue an open relevant PR;
after it merges, create a fresh branch from the updated main.
