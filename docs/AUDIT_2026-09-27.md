## Confirmed and corrected defects

### 1. Accepted operation failures could disappear

`RuntimeError`, `ZeroDivisionError` and other ordinary exceptions from a
registered provider or runtime-identity callback escaped the generic runner.
The attempt acquired no retained execution. On a live connection an unexpected
provider exception closed the WebSocket with code 1011. A provider-raised
`OSError` was instead misclassified by the session as a storage failure.

The runner now turns unexpected ordinary exceptions within that boundary into
a sealed `ciw.execution.v1` refusal with code `operation_failed` and no result.
The exception type is retained; arbitrary diagnostic text and the traceback go
to host logs instead of the returned record. Actual persistence failures remain
`storage_error`. `KeyboardInterrupt` and `SystemExit` still propagate; this does
not guarantee retention after process termination, resource exhaustion or disk
failure, and does not introduce a sandbox.

### 2. Empty error messages produced non-reopenable records

An otherwise ordinary `ValueError()` or declared `AdapterRefusal` with an empty
or whitespace-only message produced a sealed refusal that the offline reader
rejected. The writer could therefore save a workspace it could not reopen.

New refusal records now supply a nonempty fallback diagnostic when needed.
Nonblank messages and declared refusal/reason codes are preserved. The offline
validator is unchanged: a resealed malformed historical refusal is still
rejected before writing a destination. Existing records are not repaired.

### 3. WebSocket requests accepted duplicate JSON keys

The workspace reader rejected duplicates, but live JSON parsing silently kept
the last value. Conflicting operation types, payloads or nested channels could
therefore be dispatched from an ambiguous request. Identical duplicated values
and escaped spellings of the same key were also accepted.

The WebSocket parser now rejects duplicate keys at every object level before
request dispatch. The response is `invalid_request` without trusting an ambiguous
request ID. The connection remains available for a subsequent valid request.
This does not change origin rules, permissions or supported operation names.

## Regression evidence

Local environment: Linux, CPython 3.13.5, NumPy 2.3.5, pytest 9.0.2 and
websockets 16.0. NumPy is not the project's pinned 2.4.3, and this is not the
project's Python 3.11/3.12 CI matrix. Treat these results as local regression
evidence, not completion of the pinned native/provider qualification gates.

| Check | Untouched base | Patched source |
| --- | --- | --- |
| New regression suite | 22 failed, 8 passed | 30 passed, no skips |
| New suite plus unchanged operation-runner tests | 22 failed, 28 passed | 50 passed, no skips |
| Compile all packaged Python modules | Not separately rerun on base | Passed |
| CLI demo -> statistics -> spectrum -> workspace inspection | Not separately rerun on base | Passed |

The new tests exercise runtime-identity failures, provider failures, blank
validation/refusal messages, provider-free reopen, actual storage failures,
process-control exceptions, reservation recovery, unchanged offline rejection,
real loopback WebSockets and successful requests after rejected/failed calls.
The unchanged runner tests additionally exercise selection capture, concurrency,
capacity reservations, semantic tampering and provider-owned object isolation.

From a complete repository checkout, the focused command is:

```sh
python -m pytest -q tests/test_operation_runner.py tests/test_operation_failure_retention.py tests/test_server_json_boundary.py
python -m compileall -q src
```

The local partial-source execution used `PYTHONPATH=src`. Logs and a patch are
provided with the audit delivery; the full repository suite was not rerun
locally because the complete checkout and all provider environments were not
available. No numerical equations, tolerances, covariance rules, source pins,
license grants or recorded identity schemas change in this patch.

## CI observations and remaining work

At inspection, the base run's Linux Python 3.11/3.12 jobs, installed-package
job, Godot bridge, container deployment and native Windows deployment passed.
The PLSR Ubuntu job (`108658538397`) failed during the private pinned provider's
Git clone, before its numerical tests: Git could not obtain GitHub credentials.
The Windows PLSR counterpart was cancelled after an install failure; the Windows
Python test jobs were still running at that inspection. These are observations
of the base commit, not passes for this patch.

Provider access remains an open operational issue. Do not disable tests, weaken
pins, publish private provider source or expose credentials to untrusted PR
code merely to make CI green. Repository branch protection also reported disabled
at inspection; this patch changes no repository settings.

Concurrent draft PRs #16 (device gateway specification) and #18 (licensing
policy) were left untouched. This audit does not merge those proposals or claim
that their implementations are present. The fix PR needs review and the normal
repository CI; broader native, browser, cryptographic and physical qualification
remain separate work.
