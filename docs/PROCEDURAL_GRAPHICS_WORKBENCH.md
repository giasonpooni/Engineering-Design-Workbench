# Procedural graphics workbench

NET's graphics workload turns bounded algebraic notation into an implicit mesh, a parametric mesh, or a procedural RGB texture. It retains the declared program and execution, independently checks the numerical artifact, and provides a local WebGL preview. Visual appearance and generated shader source do not establish physical material properties.

The loop is **author → preview → retain → inspect → verify → replay → export**. Browser previews are transient. Retaining a result creates the same Session evidence, operation, execution, result, and verification records used by NET's other workloads.

## Start the workbench

From the repository root, create a Python environment and install the runtime:

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install .
```

On Windows PowerShell, activate with `.venv\Scripts\Activate.ps1`, or run `.venv\Scripts\python.exe` and `.venv\Scripts\net.exe` directly. Development checks use `python -m pip install ".[dev]"`. Interactive rendering uses WebGL in the browser; a separate Python GPU package is not required.

Start the local editor:

```sh
net graphics serve --output-dir graphics-history --port 8788
```

Open `http://127.0.0.1:8788`. The server binds to the local loopback address. Its API accepts the declared graphics workload and server-generated run identifiers; a browser request cannot select an arbitrary output path, executable provider, or filesystem file.

Choose an implicit, parametric, or texture example; edit its notation and declared parameters; preview the result; then retain a run when its definition is ready to record. Geometry previews support orbiting, zooming, and edge display. The **High contrast** control changes the interface presentation without altering the definition or retained numerical artifact. A viewport screenshot is not the reproducibility identity of a mesh or a CPU-baked texture.

## Run the same programs from the terminal

An implicit gyroid band:

```sh
net graphics example --profile gyroid --output gyroid.json
net graphics run gyroid.json --output-dir retained-gyroid
net graphics inspect retained-gyroid
net graphics verify retained-gyroid
net graphics replay retained-gyroid --output-dir replayed-gyroid
net graphics export retained-gyroid --format obj --output gyroid.obj
net graphics export retained-gyroid --format json --output gyroid-mesh.json
```

A transformed parametric torus:

```sh
net graphics example --profile parametric --output parametric.json
net graphics run parametric.json --output-dir retained-parametric
net graphics inspect retained-parametric
net graphics verify retained-parametric
net graphics replay retained-parametric --output-dir replayed-parametric
net graphics export retained-parametric --format obj --output parametric.obj
net graphics export retained-parametric --format json --output parametric-mesh.json
```

A CPU-baked RGB texture with generated GLSL preview source:

```sh
net graphics example --profile texture --output texture.json
net graphics run texture.json --output-dir retained-texture
net graphics inspect retained-texture
net graphics verify retained-texture
net graphics replay retained-texture --output-dir replayed-texture
net graphics export retained-texture --format png --output texture.png
net graphics export retained-texture --format json --output texture-artifact.json
```

Outputs are create-only. Choose a new request filename, retained directory, replay directory, or export filename when repeating a command. Inspection and fresh verification preserve the retained files. Meshes support OBJ and JSON export; textures support PNG and JSON export. Unsupported representation conversions are refused.

The checked-in [examples](../examples/procedural/README.md) contain complete request JSON generated by the installed example APIs. They are procedural demonstrations, not acquired measurements or qualified manufacturing designs.

## Three representation contracts

| Representation | Notation | Sampling and output |
| --- | --- | --- |
| Implicit geometry | One scalar field of `x`, `y`, `z` | Zero isosurface on a bounded Cartesian grid; triangle mesh with grid-edge lineage |
| Parametric geometry | Three position expressions of `u`, `v` | Declared UV lattice, periodicity, and tessellation; triangle mesh with each vertex's UV coordinate |
| Procedural texture | Three RGB channel expressions of `u`, `v` | Pixel-center sampling; clipped, opaque RGBA8 bytes; PNG and emitted GLSL source |

Mesh coordinates use `normalized_length` in `procedural.local_xyz.v1`. They do not acquire metres, mass, modulus, composition, or strength through export. UV parameters are dimensionless; trigonometric functions take radians. The torus example's two UV parameters represent angles, while its rotation angle is a separately declared parameter.

Texture coordinates use `normalized_coordinates` in `procedural.texture_uv.v1`. Resolution is `[width, height]`: columns advance through `u`; rows advance through `v`. The first PNG row samples just above the lower `v` bound; the first column samples just above the lower `u` bound. At column `i` and row `j`, the sample is

\[
u_i=u_0+(i+\tfrac12)(u_1-u_0)/W,\qquad
v_j=v_0+(j+\tfrac12)(v_1-v_0)/H.
\]

RGB values are clipped to `[0,1]`, then each channel is quantized using `floor(255*c+0.5)`. Alpha is fixed at 255. The declared colour interpretation is unqualified display RGB, without an optical calibration or a physical material model.

## Geometry definitions

The gyroid example defines

\[
F(x,y,z)=\sin(kx)\cos(ky)+\sin(ky)\cos(kz)+\sin(kz)\cos(kx),
\]

then extracts the zero surface of `abs(F)-tau`. Its negative region is the band \(|F|<\tau\). The parameter `tau` is a field threshold, not a uniform geometric wall thickness. Boundary clipping is retained and checked rather than silently capped.

The parametric torus starts with

\[
\mathbf p(u,v)=((R+r\cos v)\cos u,\;(R+r\cos v)\sin u,\;r\sin v).
\]

Its example applies a rotation about the Y axis directly in the three coordinate expressions. Translation, scaling, and other coordinate transforms can likewise be declared in those expressions. The two periodic axes omit duplicate endpoint vertices and wrap connectivity; the verifier separately samples declared seam agreement. A periodic declaration alone does not establish a continuous, embedded, or self-intersection-free surface.

## Safe notation, typed IR, and budgets

The interpreter accepts `+`, `-`, `*`, `/`, unary signs, and powers with literal integer exponents from 0 through 6. Functions are `sin`, `cos`, `abs`, `sqrt` (one argument), and `min`, `max` (two arguments). A definition may contain at most eight declared parameters. Coordinate names and built-in function names are reserved; UV programs use `u`, `v` and cannot silently substitute Cartesian `x`, `y`, `z`.

Evaluation uses binary64 arithmetic. A nonzero notation literal that would round down to zero is rejected. The interpreter does not execute Python or JavaScript. Attributes, indexing, comprehensions, arbitrary calls, undeclared symbols, and nonfinite or out-of-budget evaluations are rejected.

| Budget | Limit |
| --- | --- |
| Each expression | 1,024 characters, 128 AST nodes, depth 16 |
| Parameter identifiers | ASCII, at most 32 characters, excluding reserved symbols/functions |
| Parameters and intermediate field values | Finite absolute value at most 1,000,000 |
| Cartesian/UV domain bounds | Within −10 to 10; each axis span at least 0.1 |
| Implicit grid | Integer resolution 8 through 24 cells per axis |
| Parametric grid | Two integer resolutions, each 8 through 48 cells |
| Texture dimensions | Integer width and height, each 16 through 256 pixels |
| Generated mesh | At most 40,000 vertices, 65,536 triangles |
| Artifact and intake files | Request intake at most 64 KiB; regular artifacts at most 8 MiB, except workspace at most 32 MiB |
| CPU generation | Cooperative 15-second deadline, checked at stages and outer loops |
| Local editor history | At most 64 retained run directories, including refusals; use a new history root when full |

The generation deadline reports a refusal when a cooperative check observes the limit. It is not an operating-system kill timer, an interruption of every numerical call, or a GPU timer. A local qualification at the maximum declared resolutions observed approximately 0.02–1.05 seconds generation and about 59 MiB Python CPU process peak for the example workloads. Browser and GPU memory are excluded. Those measurements describe that Python 3.12.14/NumPy 2.4.3 environment; they do not guarantee latency or memory on other machines or for every accepted expression.

Implicit extraction uses the installed six-tetrahedra subdivision of each grid cube and linear edge interpolation. Exact-zero samples share a canonical grid-vertex source and are classified outside. The compiler removes exact zero-area and duplicate triangles, then drops unused vertices. It does not smooth, fill holes, or repair solids.

Parametric coordinates and RGB channels compile to inert typed scalar IR. Each retained IR tree is bound to its authored expression and parameter values. GLSL is emitted only from that validated tree; authored text is not inserted as executable shader source. Integer powers use fixed helpers to preserve bounded integer-power semantics for negative bases.

The retained shader records source emission with `compilation: not_performed`. The browser can compile and preview the emitted shader using its local graphics implementation. CPU pixel verification does not establish GPU compilation on another device or GPU/CPU pixel equality. Browser precision, rasterization, and display behaviour remain separate from the retained CPU image identity. Mesh preview uses an approximate material display shader with visual roughness and metallic controls. The generated texture shader is unlit RGB; those retained appearance fields do not change its baked pixels or unlit preview, and the texture UI disables their controls. They supply no composition or mechanical model.

## Records and identities

| Record | Meaning |
| --- | --- |
| Request and source evidence | Declared notation, parameters, coordinates, sampling, representation, and appearance |
| Generation operation | Fixed, installed graphics provider selected by trusted code |
| Execution and result | One occurrence of generation and its retained output |
| Numerical output identity | Generated mesh or texture identity, separate from its occurrence |
| Verification occurrence | Separate numerical checks bound to that candidate |
| Replay | Fresh execution of the retained request, compared with the retained output |

Repeated execution of an unchanged definition preserves source evidence and deterministic numerical output within the recorded runtime and arithmetic environment. Each run creates fresh execution, result, and verification occurrence identities. Appearance changes affect source and artifact identity even when the underlying mesh or RGB samples remain unchanged. Fresh verification recomputes checks on an existing candidate without rewriting its retained history or inventing a new retained execution.

Static inspection validates saved structure, seals, identity bindings, typed IR/source consistency, and declared dependencies without running the field evaluator, generator, numerical verifier, GPU compiler, or PNG decoder. Content seals identify retained declarations; they do not authenticate an author or establish a geometric property. Use `verify` to recompute the numerical checks.

An operation refusal retains its attempted execution diagnostic without inventing a completed result for that operation. A completed numerical verification can instead report `FAIL`: that retains the candidate, verification occurrence, and failed checks. Both remain inspectable alongside successful runs and cannot be replayed or exported as qualified results. The summary distinguishes `PASS`, `FAIL`, and `not_verified`; only `PASS` supports a qualified export.

## What verification establishes

Mesh checks include boundary and nonmanifold edges, vertex links, winding consistency, connected components, duplicate or degenerate faces, unused vertices, coincident vertices, area, bounds, and declared closure. Implicit checks additionally test grid-edge interpolation lineage and continuous field residual at generated vertices. Parametric checks additionally test the canonical UV lattice/connectivity, sampled XYZ mapping, declared periodic seams, and orientation relative to sampled parameter derivatives.

Implicit residual tolerance is in the scalar field value: rescaling a field changes its residual without changing its zero surface. Parametric position residual is the largest absolute XYZ component difference at retained UV samples. Neither is a general global bound on geometric distance.

Texture checks independently reopen the PNG signature, dimensions, chunk structure, CRCs, bounded deflate stream, row filters, and exact RGBA bytes. They compare those decoded bytes with both the retained RGBA and a fresh CPU evaluation of the channel notation at every declared pixel center. This verifies the declared discrete image, not the appearance on an arbitrary monitor or GPU.

These are finite checks under declared sampling and arithmetic contracts. A mesh may miss features smaller than its grid. The independent audit includes a polynomial field that is exactly zero on extraction nodes but differs between them: its flat mesh passes vertex checks while continuous fidelity remains explicitly unestablished. Vertex residuals do not bound field values over triangle interiors; sampled UV seams do not establish seam agreement at every continuous parameter. Grid refinement and analytic benchmark comparisons add evidence where those properties matter.

The workload does not establish self-intersection freedom, a manufacturing-ready solid, structural response, optical metrology, physical validation, or admitted industrial state. Connecting an artifact to mechanics or manufacturing requires separately qualified conversion, physical units, material models, boundary conditions, and validation scope.

## Exports and limits

OBJ preserves generated coordinates and triangle connectivity. PNG preserves the declared baked RGBA8 image using the bounded encoder profile. Their adjacent identity sidecars bind exported bytes to the source, retained execution, numerical artifact, checks, and authority declarations. Keep each sidecar with its export. JSON export retains the numerical artifact, request, generated source/IR where present, and verification metadata.

Export requires fresh numerical verification. PNG export additionally independently reopens the proposed PNG before publication. Failed or unqualified candidates remain inspectable but cannot become qualified exports. Export does not upgrade a visual mesh into a CAD solid, a texture into an optical measurement, or appearance into a physical material.

The implemented slice covers implicit and parametric geometry, procedural RGB textures, generated GLSL preview source, parameter controls, visual appearance, high-contrast presentation, retained Session workflows, and OBJ/PNG/JSON export. Unrestricted shader-language execution, arbitrary image operators, editable polygon tooling, CAD-solid operations, and physical material simulation need their own providers and conversion qualifications. They can extend this workload through the existing substrate without changing the meaning of retained evidence.

The integrated implementation uses main's shared command catalogue for `net graphics` help, discovery, and lazy dispatch. Its operator tests also reproduce eight original provider checkouts from retained Git history; checkout identity does not establish provider science. These results qualify the bounded local demo on Linux/Python 3.12.14 with Chromium 140.0.7339.186 and Playwright 1.62.1. The observed WebGL backend was ANGLE/SwiftShader; this establishes actual shader compilation and display through that API, without establishing a hardware GPU or general GPU/CPU pixel identity. The configured Linux/Windows and Python 3.11/3.12 CI matrix reports its own execution evidence separately.

Source checks and wheel qualification are separate:

```sh
python -m pip install ".[dev]" build
python -m pytest tests/test_procedural_core.py tests/test_procedural_representations.py tests/test_procedural_verification.py tests/test_procedural_representation_verification.py tests/test_procedural_workflow.py tests/test_procedural_integration_audit.py
python -m build --wheel --outdir dist
python -m pip install --force-reinstall --no-deps dist/computational_instrumentation_workbench-0.1.0-py3-none-any.whl
python scripts/check_procedural_installed.py --net .venv/bin/net --output-dir results/graphics-installed
```

On Windows, pass `.venv\Scripts\net.exe` to the installed qualifier. Its output directory must be new. The qualifier runs the actual installed command outside the source checkout, exercising all five example profiles, retained inspection, fresh verification, replay, exports, and honest refusals.

Browser qualification requires Node 20 or newer and pinned Playwright 1.62.1. Install that validation dependency and Chromium, then run the portable qualifier with an absolute NET executable path:

```sh
npm install --no-save playwright@1.62.1
npx playwright install chromium
NODE_PATH="$(pwd)/node_modules" node validation/procedural_browser.cjs --net "$(pwd)/.venv/bin/net" --output-dir results/graphics-browser
```

For PowerShell:

```powershell
$env:NODE_PATH = (Resolve-Path node_modules).Path
node validation/procedural_browser.cjs --net (Resolve-Path .venv\Scripts\net.exe).Path --output-dir results\graphics-browser
```

The qualifier retains its report, screenshots, downloads, and run bundles. It checks actual shader compilation and browser interaction, failure/no-WebGL branches, high contrast, mobile layout, and retained export/replay. That browser evidence does not establish GPU/CPU pixel equality or physical validation.
